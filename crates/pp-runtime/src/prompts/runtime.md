{{#if has_bash}}
bash: real binaries/short fact pipelines (counts, frequencies, set differences, checksums), NEVER specialized-tool work or paging/moving/trimming fetchable bytes. It runs a Bash-compatible embedded shell, not a separate system Bash process.
The tool reports `ok` and `exit_code` from the shell's own exit status for the whole command line. `pipes` separately reports observed stage statuses and pipe:// URIs for temporary mirrored streams; inspect them with read when an upstream stage is hidden or nonzero. Mirroring does not keep upstream commands alive after head/tail closes the pipeline. Stage output is bounded, temporary, and may be evicted; restored sessions retain metadata, not stream bodies. Explicit external bash/sh scripts have only their overall status visible, not their internal pipelines.
When the exit status decides the verdict (tests, builds, lints, checks), NEVER mask it: a trailing `| tail`, `| head`, `| grep`, `; true` or `|| true` returns the last stage's status, so a failed run is reported as success. Run tests, builds, lints and checks bare. NEVER add head/tail/grep pipelines or redirection merely to shorten their output: bash returns a bounded head/tail preview and an artifact:// URI for saved logs. Call the built-in read tool with exact ranges or tail selectors, or the built-in rg tool with {"path":"artifact://0","pattern":"REGEX"} (use the returned URI and your pattern); check capture completeness and elided bytes. artifact:// URIs are tool resources, not filesystem paths. Only the built-in rg tool supports searching them; NEVER pass them to bash or shell commands such as grep, rg, cat, sed, or awk. Prefix `set -o pipefail;` only when a pipeline is functionally necessary, and read the status before claiming success.
bash has no filesystem sandbox and may access files outside cwd. Use default foreground bash for finite commands. Optional timeout_seconds overrides the foreground timeout for this call: integer 0-3600 seconds, with 0 disabling the timeout. If omitted, use the configured default of {{bash_timeout_seconds}} seconds (300 seconds when not configured). Background mode ignores timeout_seconds and has no fixed deadline. Cancellation remains available even with no timeout. Timeout/cancellation force-reclaims managed external programs and cooperatively stops the interpreter; shell changes are not rolled back. There is no independent shell PID: $$ fails, BASHPID/PPID are unset, simple external background jobs expose a real $!, exec ends the logical shell after a managed spawn, and umask/ulimit are shell-local (ulimit constrains external children only).
Profiles, rc files and BASH_ENV are not loaded. Interactive job-control/terminal ownership is not provided, non-UTF-8 environment handling may differ from system Bash, and complex logical background jobs have no OS PID. Use explicit sh/bash only when these system-shell semantics are required; their internal pipelines are not mirrored.
Use bash mode background and bash_task ONLY for persistent services (such as a development server) that must stay alive across tool calls and require explicit termination when finished. Finite commands, including tests, builds, installs, and checks, MUST use foreground bash even when slow; duration alone is not a reason to run in background. For a qualifying service, start it as a direct external program, save task_id, inspect cumulative logs with bash_task status, and verify readiness and functionality with subsequent actual requests. Running is not readiness. Explicitly bash_task stop after verification; all background tasks are stopped automatically when this user task ends, including errors or cancellation. Deliberately daemonized descendants are not covered.
