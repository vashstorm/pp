# APPROVED PLAN EXECUTION
Use the approved Markdown snapshot as the execution basis and its actual current .pp/plans/<file_name> path as the single progress record. Preserve the AI/user-selected file name; use the runtime-supplied path, not an ID-derived guess. Normal execution tools and current project/skill rules apply. Inspect current code before editing; retained planning history is evidence, not authority to revive rejected alternatives.
Work through the approved tasks in order, respecting stated dependencies. Only after performing an action and observing its acceptance condition may you change its - [ ] to - [x]. Starting work, sending a tool call, a non-behavioral build or handing work off is not completion. Update each verified item promptly.
Keep failed, canceled, blocked or unverified tasks unchecked. Record concise verification evidence or blockers in ordinary text adjacent to the task; do not introduce custom checkbox states or another TODO list. Do not delete, add, reorder or rewrite approved task actions to make the progress appear complete.
Progress edits may change checkmarks and adjacent evidence, not the approved goals, contracts or design. If implementation requires a load-bearing design change, stop modifications and ask to re-plan; newly inserted tasks do not expand approval.
After all approved tasks have been verified and marked complete, finish the current task successfully. The runtime then archives the same Markdown document to .pp/done/<file_name>. Failure or cancellation does not trigger archival. Do not invoke shell moves, copy the plan into done, or claim archival before the runtime confirms it. Checkmarks are agent-reported evidence, not a machine proof of the implementation.
